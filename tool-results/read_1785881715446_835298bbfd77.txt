padding-left: 0.375em;\"></a></h3><i class=\"icon-arrow-up back-to-top\"> </i>\n\n<p>The <code class=\"language-plaintext highlighter-rouge\">Update Sequence Number Journal (USN) Journal</code> is a feature of NTFS,\nactivated by default on Vista and later, which maintains a record of changes\nmade to the NTFS volume. The creation, deletion or modification of files or\ndirectories are for instance journalized.</p>\n\n<p>The records in the <code class=\"language-plaintext highlighter-rouge\">UsnJrnl</code> are progressively overwritten once the max size of\nthe journal has been reached. The <code class=\"language-plaintext highlighter-rouge\">UsnJrnl</code> usually contains historical data on\nthe last few days (1-3 days for system full time use, &lt; 7 days for regular\nsystem use).</p>\n\n<h3 id=\"information-of-interest\" class=\"clickable-header top-level-header\">Information of interest<a class=\"anchorjs-link \" aria-label=\"Anchor\" data-anchorjs-icon=\"\" href=\"#information-of-interest\" style=\"font: 1em / 1 anchorjs-icons; padding-left: 0.375em;\"></a></h3><i class=\"icon-arrow-up back-to-top\"> </i>\n\n<p>The <code class=\"language-plaintext highlighter-rouge\">UsnJrnl</code> is composed of two named data streams:</p>\n\n<ul>\n  <li>\n    <p>The <code class=\"language-plaintext highlighter-rouge\">$Max</code> stream stores the metadata of the change.</p>\n  </li>\n  <li>\n    <p>The <code class=\"language-plaintext highlighter-rouge\">$J</code>  stream stores the actual change log records.</p>\n  </li>\n</ul>\n\n<p>Each change log record is notably composed of:</p>\n\n<ul>\n  <li>\n    <p>an <code class=\"language-plaintext highlighter-rouge\">Update Sequence Number (USN)</code>.</p>\n  </li>\n  <li>\n    <p>The timestamp of the change.</p>\n  </li>\n  <li>\n    <p>The reason/operation of the record (<code class=\"language-plaintext highlighter-rouge\">USN_REASON_FILE_CREATE</code>,\n<code class=\"language-plaintext highlighter-rouge\">USN_REASON_FILE_DELETE</code>, <code class=\"language-plaintext highlighter-rouge\">USN_REASON_DATA_OVERWRITE</code>,\n<code class=\"language-plaintext highlighter-rouge\">USN_REASON_RENAME_NEW_NAME</code>, etc.).</p>\n  </li>\n  <li>\n    <p>The name of the file or folder impacted by the change.</p>\n  </li>\n  <li>\n    <p>The <a href=\"https://learn.microsoft.com/en-us/windows/win32/fileio/file-attribute-constants\">file attribute</a>\nof the entry, which can notably be used to determine whether an entry is a\nfile or a directory (<code class=\"language-plaintext highlighter-rouge\">FILE_ATTRIBUTE_DIRECTORY</code>).</p>\n  </li>\n  <li>\n    <p>The <code class=\"language-plaintext highlighter-rouge\">MFT</code> <code class=\"language-plaintext highlighter-rouge\">entry</code> and <code class=\"language-plaintext highlighter-rouge\">sequence</code> numbers of the file impacted by the change,\nas well as its parent’s <code class=\"language-plaintext highlighter-rouge\">MFT</code> <code class=\"language-plaintext highlighter-rouge\">entry</code> and <code class=\"language-plaintext highlighter-rouge\">sequence</code> numbers.</p>\n  </li>\n</ul>\n\n<h4 id=\"deducing-an-entry-path-using-the-mft\" class=\"clickable-header\">Deducing an entry path using the MFT<a class=\"anchorjs-link \" aria-label=\"Anchor\" data-anchorjs-icon=\"\" href=\"#deducing-an-entry-path-using-the-mft\" style=\"font: 1em / 1 anchorjs-icons; padding-left: 0.375em;\"></a></h4>\n\n<p>As each change log record contains the <code class=\"language-plaintext highlighter-rouge\">MFT</code> <code class=\"language-plaintext highlighter-rouge\">entry</code> and\n<code class=\"language-plaintext highlighter-rouge\">sequence</code> numbers and the direct parent <code class=\"language-plaintext highlighter-rouge\">entry</code> and <code class=\"language-plaintext highlighter-rouge\">sequence</code> numbers of the\nfile concerned by the change, it is possible to retrieve the location of the\nfile using the <code class=\"language-plaintext highlighter-rouge\">MFT</code>.</p>\n\n<p>However, as the files and parent folder(s) of files referenced in the <code class=\"language-plaintext highlighter-rouge\">UsnJrnl</code>\nmay have been deleted and may no longer be present in the <code class=\"language-plaintext highlighter-rouge\">MFT</code>, simply\nsearching for records with matching <code class=\"language-plaintext highlighter-rouge\">entry</code> and <code class=\"language-plaintext highlighter-rouge\">sequence</code> numbers in the <code class=\"language-plaintext highlighter-rouge\">MFT</code>\ncan lead to unresolved or inconsistent paths. Indeed, when a file is deleted\nfrom the volume, its associated <code class=\"language-plaintext highlighter-rouge\">MFT</code> <code class=\"language-plaintext highlighter-rouge\">file record</code> is set as no longer in use\nand the metadata of the <code class=\"language-plaintext highlighter-rouge\">file record</code> are overwritten with that of the new\nentry (when the <code class=\"language-plaintext highlighter-rouge\">file record</code> gets re-used). The <code class=\"language-plaintext highlighter-rouge\">MFT</code> <code class=\"language-plaintext highlighter-rouge\">file record</code> <code class=\"language-plaintext highlighter-rouge\">entry</code>\nnumber remains unchanged with only the <code class=\"language-plaintext highlighter-rouge\">file record</code> <code class=\"language-plaintext highlighter-rouge\">sequence</code> number being\nincreased by one.</p>\n\n<p>Thus, matching the <code class=\"language-plaintext highlighter-rouge\">UsnJrnl</code> to the current state of the <code class=\"language-plaintext highlighter-rouge\">MFT</code> will result:</p>\n\n<ul>\n  <li>\n    <p>In some invalid paths if only the <code class=\"language-plaintext highlighter-rouge\">file record</code>’s <code class=\"language-plaintext highlighter-rouge\">entry</code> numbers are used\nto find the files location. highlighter-rouge\">entry</code> and <code class=\"language-plaintext highlighter-rouge\">sequence</code>\nnumbers are used, as deleted entries referenced in the <code class=\"language-plaintext highlighter-rouge\">UsnJrnl</code> have an\n<code class=\"language-plaintext highlighter-rouge\">entry</code> and <code class=\"language-plaintext highlighter-rouge\">sequence</code> numbers combination that no longer exist in the\n<code class=\"language-plaintext highlighter-rouge\">MFT</code>.</p>\n  </li>\n</ul>\n\n<p>Additionally, renaming or moving files or folders does not change the <code class=\"language-plaintext highlighter-rouge\">MFT</code>\n<code class=\"language-plaintext highlighter-rouge\">file record</code> <code class=\"language-plaintext highlighter-rouge\">entry</code> or <code class=\"language-plaintext highlighter-rouge\">sequence</code> numbers, potentially leading to invalid\npaths if only the <code class=\"language-plaintext highlighter-rouge\">MFT</code> is used to the location of files referenced in the\n<code class=\"language-plaintext highlighter-rouge\">UsnJrnl</code>.</p>\n\n<p>A technique to exhaustively and accurately rebuild the location of files found\nin the <code class=\"language-plaintext highlighter-rouge\">UsnJrnl</code> is implemented by\n<a href=\"https://github.com/CyberCX-DFIR/usnjrnl_rewind\">usnjrnl_rewind</a>.\n<code class=\"language-plaintext highlighter-rouge\">usnjrnl_rewind</code> “rewinds” the <code class=\"language-plaintext highlighter-rouge\">UsnJrnl</code>, reading the journal in reverse (from\nthe last, most recent change to the first, oldest change) and keeping stateful\ninformation (in a local <code class=\"language-plaintext highlighter-rouge\">SQL</code> database) about every entry’s <code class=\"language-plaintext highlighter-rouge\">entry</code> and\n<code class=\"language-plaintext highlighter-rouge\">sequence</code> numbers and parent’s <code class=\"language-plaintext highlighter-rouge\">entry</code> and <code class=\"language-plaintext highlighter-rouge\">sequence</code> numbers. Using this\ntechnique it is thus possible to rebuild a file location as it was when the\nchange operation ocurred. Indeed every entry’s <code class=\"language-plaintext highlighter-rouge\">entry</code> and <code class=\"language-plaintext highlighter-rouge\">sequence</code> numbers\nin the file’s path are either in the <code class=\"language-plaintext highlighter-rouge\">MFT</code> (if unchanged since the operation)\nor referenced by an operation in the <code class=\"language-plaintext highlighter-rouge\">UsnJrnl</code> (as changes impacting the file\nlocation would have occurred after the file change operation).</p>\n\n<p>More details on this technique can be found in\n<a href=\"https://cybercx.com.au/blog/ntfs-usnjrnl-rewind/\">CyberCX Blog’s NTFS Usnjrnl Rewind</a>.</p>\n\n<div class=\"language-bash highlighter-rouge\"><div class=\"highlight\"><pre class=\"highlight\"><code>python usnjrnl_rewind.py <span class=\"nt\">-m</span> <span class=\"s2\">\"&lt;MFT_CSV&gt;\"</span> <span class=\"nt\">-u</span> <span
