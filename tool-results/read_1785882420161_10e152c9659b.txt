The user always receives one or more <b>USN_RECORD_V4</b> records followed by one <a href=\"/en-us/windows/desktop/api/winioctl/ns-winioctl-usn_record_v3\" data-linktype=\"absolute-path\">USN_RECORD_V3</a> record.</p>\n<p>To provide a path forward compatibility in change journal clients, Microsoft provides a major and minor version number of the change journal software in the <b>USN_RECORD_V4</b> structure. Your code should examine these values, examine its own compatibility with the change journal software, and gracefully handle any incompatibility if necessary.</p>\n<p>A change in the minor version number indicates that the existing <b>USN_RECORD_V4</b> structure members are still valid, but that new members may have been added between the penultimate member and the last, which is a variable-length string.</p>\n<p>To handle such a change gracefully, your code should not do any compile-time pointer arithmetic that relies on the location of the last member. For example, a change in the minor version number makes the <code>sizeof(USN_RECORD)</code> call unreliable. Instead, rely on run-time calculations that use the <b>RecordLength</b> member.</p>\n<p>An increase in the major version number of the change journal software indicates that the <b>USN_RECORD_V4</b> structure may have undergone major changes, and that the current definition may not be reliable. If your code detects a change in the major version number of the change journal software, the code should not work with the change journal.</p>\n<p>For more information, see <a href=\"/en-us/windows/desktop/FileIO/creating-modifying-and-deleting-a-change-journal\" data-linktype=\"absolute-path\">Creating, Modifying, and Deleting a Change Journal</a>.</p>\n<div
