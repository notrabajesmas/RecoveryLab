I covered different artifacts that can be useful when conducting incident response. In the last article of those series, I covered The NTFS INDX attribute which is used to store metadata about files inside directories and the $LogFile metadata file, which keeps record of all operations that occurred in the NTFS volume. Both these artifacts can give the investigator a great amount of information about attacker activity. However, there is another special file inside NTFS that also contains a wealth of historical information about operations that occurred on the NTFS volume, the Update Sequence Number (USN) <a href=\"https://msdn.microsoft.com/en-us/library/windows/desktop/aa363798%28v=vs.85%29.aspx\">journal file</a> named $UsnJrnl.</p>\n<p>While the different file operations occur on disk, in a NTFS volume, the change journal <a href=\"https://msdn.microsoft.com/en-us/library/aa365722.aspx\">keeps record of the reason</a> behind the operation such as file creation, deletion, encryption, directory creation, deletion, etc. There is a USN change journal per volume, its turned on by default since Windows Vista, and used by applications such as the Indexing Service, File Replication Service (FRS), Remote Installation Services (RIS), and Remote Storage. Nonetheless, applications and Administrators can create, delete, and re-create change journals. The change journal file is stored in the hidden system file $Extend\\$UsnJrnl. The <a href=\"http://forensicinsight.org/wp-content/uploads/2013/07/F-INSIGHT-Advanced-UsnJrnl-Forensics-English.pdf\">$UsnJrnl</a> file contains two alternate data streams (ADS). The $Max and the $J. The $Max data streams contains information about the change journal such as the maximum size. The $J data stream contains the contents of the change journal and includes information such as the date and time of the change, the reason for the change, the MFT entry, the MFT parent entry and others. This information can useful for an investigation, for example, in a scenario where the attacker is deleting files and directories while he moves inside an organization in order to hide his tracks. To obtain the change journal file you need raw access to the file system.</p>\n<p>So, on a live system, you could check the size and status of the change journal by running the command “fsutil usn queryjournal C:” on a Windows command prompt with administrator privileges. The “<a href=\"https://technet.microsoft.com/en-us/library/cc788042(WS.10).aspx\">fsutil</a>” command can also be used to <a href=\"http://faq.attix5.com/index.php?View=entry&amp;EntryID=24\">change the size of the journal</a>. Fom a live system, you could also obtain the change journal file using a tool like <a href=\"https://github.com/jschicht/RawCopy\">RawCopy </a>or <a href=\"https://github.com/jschicht/ExtractUsnJrnl\">ExtractUsnJrnl&nbsp;</a>from Joakim Schicht. In this particular system the maximum size of the change journal is 0x2000000 bytes.</p>\n<p><a href=\"https://countuponsecurity.com/wp-content/uploads/2017/05/usnjrnl-fsutil.png\"><img data-attachment-id=\"3809\" data-permalink=\"https://countuponsecurity.com/2017/05/25/digital-forensics-ntfs-change-journal/usnjrnl-fsutil/\" data-orig-file=\"https://countuponsecurity.com/wp-content/uploads/2017/05/usnjrnl-fsutil.png\" data-orig-size=\"929,320\" data-comments-opened=\"1\" data-image-meta=\"{&quot;aperture&quot;:&quot;0&quot;,&quot;credit&quot;:&quot;&quot;,&quot;camera&quot;:&quot;&quot;,&quot;caption&quot;:&quot;&quot;,&quot;created_timestamp&quot;:&quot;0&quot;,&quot;copyright&quot;:&quot;&quot;,&quot;focal_length&quot;:&quot;0&quot;,&quot;iso&quot;:&quot;0&quot;,&quot;shutter_speed&quot;:&quot;0&quot;,&quot;title&quot;:&quot;&quot;,&quot;orientation&quot;:&quot;0&quot;}\" data-image-title=\"usnjrnl-fsutil\" data-image-description=\"\" data-image-caption=\"\" data-large-file=\"https://countuponsecurity.com/wp-content/uploads/2017/05/usnjrnl-fsutil.png?w=580\" class=\"aligncenter size-large wp-image-3809\" src=\"https://countuponsecurity.com/wp-content/uploads/2017/05/usnjrnl-fsutil.png?w=580&amp;h=200\" alt=\"\" width=\"580\" height=\"200\" srcset=\"https://countuponsecurity.com/wp-content/uploads/2017/05/usnjrnl-fsutil.png?w=580 580w, https://countuponsecurity.com/wp-content/uploads/2017/05/usnjrnl-fsutil.png?w=150 150w, https://countuponsecurity.com/wp-content/uploads/2017/05/usnjrnl-fsutil.png?w=300 300w, https://countuponsecurity.com/wp-content/uploads/2017/05/usnjrnl-fsutil.png?w=768 768w, https://countuponsecurity.com/wp-content/uploads/2017/05/usnjrnl-fsutil.png 929w\" sizes=\"(max-width: 580px) 100vw, 580px\"></a>Now, let’s perform a&nbsp;quick exercise about obtaining the change journal file from a disk image. First, we use the “mmls” utility to see the partition table from the disk image. Then, we use “fls” from The Sleuth Kit to obtain a file and directory listing and grep for the UsnJrnl string. As you could see in the picture below the output of “fls” shows that the filesystem contains the $UsnJrnl:$Max and $UsnJrnl:$J files. We are interested in the MFT entry number which is 84621.</p>\n<p><a href=\"https://countuponsecurity.com/wp-content/uploads/2017/05/usnjrnl-mmls.png\"><img data-attachment-id=\"3811\" data-permalink=\"https://countuponsecurity.com/2017/05/25/digital-forensics-ntfs-change-journal/usnjrnl-mmls/\" data-orig-file=\"https://countuponsecurity.com/wp-content/uploads/2017/05/usnjrnl-mmls.png\" data-orig-size=\"1803,671\" data-comments-opened=\"1\" data-image-meta=\"{&quot;aperture&quot;:&quot;0&quot;,&quot;credit&quot;:&quot;&quot;,&quot;camera&quot;:&quot;&quot;,&quot;caption&quot;:&quot;&quot;,&quot;created_timestamp&quot;:&quot;0&quot;,&quot;copyright&quot;:&quot;&quot;,&quot;focal_length&quot;:&quot;0&quot;,&quot;iso&quot;:&quot;0&quot;,&quot;shutter_speed&quot;:&quot;0&quot;,&quot;title&quot;:&quot;&quot;,&quot;orientation&quot;:&quot;0&quot;}\" data-image-title=\"usnjrnl-mmls\" data-image-description=\"\" data-image-caption=\"\" data-large-file=\"https://countuponsecurity.com/wp-content/uploads/2017/05/usnjrnl-mmls.png?w=580\" class=\"aligncenter size-large wp-image-3811\" src=\"https://countuponsecurity.com/wp-content/uploads/2017/05/usnjrnl-mmls.png?w=580&amp;h=216\" alt=\"\" width=\"580\" height=\"216\" srcset=\"https://countuponsecurity.com/wp-content/uploads/2017/05/usnjrnl-mmls.png?w=580 580w, https://countuponsecurity.com/wp-content/uploads/2017/05/usnjrnl-mmls.png?w=1160 1160w, https://countuponsecurity.com/wp-content/uploads/2017/05/usnjrnl-mmls.png?w=150 150w, https://countuponsecurity.com/wp-content/uploads/2017/05/usnjrnl-mmls.png?w=300 300w, https://countuponsecurity.com/wp-content/uploads/2017/05/usnjrnl-mmls.png?w=768 768w, https://countuponsecurity.com/wp-content/uploads/2017/05/usnjrnl-mmls.png?w=1024 1024w\" sizes=\"(max-width: 580px) 100vw, 580px\"></a></p>\n<p>Next, let’s review MFT record properties for the entry number 84621 with the command “istat” from The Sleuth Kit. This MFT entry stores the NTFS metadata about the $UsnJrnl. We are interested in the attributes section, more specifically, we are looking for the identifier 128 which points to the $DATA attribute. The identifier 128-37 points to the $Max data stream which is of size 32 bytes and is <a href=\"https://countuponsecurity.com/2015/11/10/digital-forensics-ntfs-metadata-timeline-creation/\">resident</a>. The identifier 128-38 points to the $J data stream which is of size 40-GBytes and sparse. Then we use the “icat” command to view the contents of the $Max data stream which can gives the maximum size of the change journal and then we also use “icat” to export the $J data stream into a file.&nbsp;Noteworthy, that the change journal is sparse. This means parts of the data is just zeros. However, icat from The Sleuth Kit will extract the full size of the data stream. A more efficient and faster tool would be ExtractUsnJrnl because it only extracts the actual data. The picture below illustrates the steps necessary to extract the change journal file.</p>\n<p><a href=\"https://countuponsecurity.com/wp-content/uploads/2017/05/usnjrnl-istat.png\"><img data-attachment-id=\"3814\" data-permalink=\"https://countuponsecurity.com/2017/05/25/digital-forensics-ntfs-change-journal/usnjrnl-istat/\" data-orig-file=\"https://countuponsecurity.com/wp-content/uploads/2017/05/usnjrnl-istat.png\" data-orig-size=\"963,813\" data-comments-opened=\"1\" data-image-meta=\"{&quot;aperture&quot;:&quot;0&quot;,&quot;credit&quot;:&quot;&quot;,&quot;camera&quot;:&quot;&quot;,&quot;caption&quot;:&quot;&quot;,&quot;created_timestamp&quot;:&quot;0&quot;,&quot;copyright&quot;:&quot;&quot;,&quot;focal_length&quot;:&quot;0&quot;,&quot;iso&quot;:&quot;0&quot;,&quot;shutter_speed&quot;:&quot;0&quot;,&quot;title&quot;:&quot;&quot;,&quot;orientation&quot;:&quot;0&quot;}\" data-image-title=\"usnjrnl-istat\" data-image-description=\"\" data-image-caption=\"\" data-large-file=\"https://countuponsecurity.com/wp-content/uploads/2017/05/usnjrnl-istat.png?w=580\" class=\"aligncenter size-large wp-image-3814\" src=\"https://countuponsecurity.com/wp-content/uploads/2017/05/usnjrnl-istat.png?w=580&amp;h=490\" alt=\"\" width=\"580\" height=\"490\" srcset=\"https://countuponsecurity.com/wp-content/uploads/2017/05/usnjrnl-istat.png?w=580 580w, https://countuponsecurity.com/wp-content/uploads/2017/05/usnjrnl-istat.png?w=150 150w, https://countuponsecurity.com/wp-content/uploads/2017/05/usnjrnl-istat.png?w=300 300w, https://countuponsecurity.com/wp-content/uploads/2017/05/usnjrnl-istat.png?w=768 768w, https://countuponsecurity.com/wp-content/uploads/2017/05/usnjrnl-istat.png 963w\" sizes=\"(max-width: 580px) 100vw, 580px\"></a><br>\nNow that we exported the change journal into a file we will use the <a href=\"https://github.com/jschicht/UsnJrnl2Csv\">UsnJrnl2Csv </a>utility. Once again another brilliant tool from Joakim Schicht. The tool supports USN_RECORD_V2 and USN_RECORD_V3, and makes it very easy to parse and extract information from the change journal. The output will be a CSV file. The picture below shows the tool in action. You just need to browse the change journal file you obtained and start parsing it.</p>\n<p><a href=\"https://countuponsecurity.com/wp-content/uploads/2017/05/usnjrnl2csv.png\"><img data-attachment-id=\"3815\" data-permalink=\"https://countuponsecurity.com/2017/05/25/digital-forensics-ntfs-change-journal/usnjrnl2csv/\" data-orig-file=\"https://countuponsecurity.com/wp-content/uploads/2017/05/usnjrnl2csv.png\" data-orig-size=\"1148,603\" data-comments-opened=\"1\" data-image-meta=\"{&quot;aperture&quot;:&quot;0&quot;,&quot;credit&quot;:&quot;&quot;,&quot;camera&quot;:&quot;&quot;,&quot;caption&quot;:&quot;&quot;,&quot;created_timestamp&quot;:&quot;0&quot;,&quot;copyright&quot;:&quot;&quot;,&quot;focal_length&quot;:&quot;0&quot;,&quot;iso&quot;:&quot;0&quot;,&quot;shutter_speed&quot;:&quot;0&quot;,&quot;title&quot;:&quot;&quot;,&quot;orientation&quot;:&quot;0&quot;}\" data-image-title=\"usnjrnl2csv\" data-image-description=\"\" data-image-caption=\"\" data-large-file=\"https://countuponsecurity.com/wp-content/uploads/2017/05/usnjrnl2csv.png?w=580\" loading=\"lazy\" class=\"aligncenter size-large wp-image-3815\" src=\"https://countuponsecurity.com/wp-content/uploads/2017/05/usnjrnl2csv.png?w=580&amp;h=305\" alt=\"\" width=\"580\" height=\"305\" srcset=\"https://countuponsecurity.com/wp-content/uploads/2017/05/usnjrnl2csv.png?w=580 580w, https://countuponsecurity.com/wp-content/uploads/2017/05/usnjrnl2csv.png?w=150 150w, https://countuponsecurity.com/wp-content/uploads/2017/05/usnjrnl2csv.png?w=300 300w, https://countuponsecurity.com/wp-content/uploads/2017/05/usnjrnl2csv.png?w=768 768w, https://countuponsecurity.com/wp-content/uploads/2017/05/usnjrnl2csv.png?w=1024 1024w, https://countuponsecurity.com/wp-content/uploads/2017/05/usnjrnl2csv.png 1148w\" sizes=\"auto, (max-width: 580px) 100vw, 580px\"></a></p>\n<p>This process might take some time, when finished, you will have a CSV file containing the journal records. This file be can easily imported into Excel. Then, filter based on the &nbsp;reason and timestamp fields. These findings can then be used as indicators of compromise in order to find more compromised systems in the environment. In addition, for each file you have the MFT entry number that could be used to attempt to recover deleted files. You might have a chance of recovering data from deleted files in case the gap between the time when the file was deleted and the image was obtained is short.</p>\n<p><a This means we can find old journal records in unallocated space on a NTFS volume. How to obtain those?
